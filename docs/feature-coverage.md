See [current first-impression validation](first-impression-validation.md) and [connected source/output proof](connected-journeys-2026-11-03.md).

Scope baseline and execution evidence refreshed November 3, 2026. The comparison concerns user outcomes, not the use of another product's branding or proprietary implementation. The searchable [dated inventory](capability-inventory-2026-11-03.md) covers all twelve capability families and 253 discovered Router models, retaining all 63 original outcomes plus new routes. Discovery, executable adapters and successful mode-specific demonstrations are distinct. Explicit demonstration records persist inside project packages and identify actual inputs, outputs, operation, take, job, request, workflow version and attribution; generic reference edits cannot certify reference-sheet/product outcomes, and lip sync cannot certify dubbing.

**Status meanings:** implemented = application behavior or model adapter exists; experimental = usable adapter whose mode-specific live result has not been validated; partial = an identified portion exists; unavailable = dependency is named and the product must not present it as working. Live proof belongs in the validation receipt, separately from implementation status.

## Official product baseline

[Higgsfield's official suite](https://higgsfield.ai/) currently presents image/video/audio creation, editing, inpainting, enhancement, cinema and marketing studios, character tools, comics, motion transfer, content-series tools and playable experiences. Its [AI Influencer description](https://higgsfield.ai/ai-influencer) ties reference images to transferred motion and variant production. These are coverage references only. Open Take Studio is independent, and its essential generation path uses BFL and MiniMax through Comfy Router.

The [Canvas introduction](https://higgsfield.ai/canvas-intro) and [Canvas help](https://higgsfield.ai/creator-hub/help-center/tools/how-do-i-use-canvas) were read explicitly. The documented baseline is an infinite node board with prompt/reference/model nodes, connected outputs, individual or sequential generation, parallel comparison, reusable workflows, autosave and live collaboration. Reference roles depend on the selected model; simply connecting an image does not establish identity consistency. The matrix below distinguishes these documented behaviors from this local application's actual capabilities.

## Continuity and inspection matrix

| Outcome | Implementation | Verification boundary |
|---|---|---|
| Take branching | Child take records preserve parent ID, source asset and input IDs | Branching is a new intended generation with a new identity, while retrying retains the old identity |
| Recorded changes | Per-field differences for model, prompt, settings, references and source | Changes describe requests, not a proof of deterministic rendering |
| Image comparisons | Side-by-side original media | No generated similarity score or identity claim |
| Video comparisons | Shared play/seek controller | Both clips start at zero and stop at the shorter duration; no looping or stretching, audio from take A only |
| Reuse earlier work | Immutable source assets are referenced by later takes | Editing motion does not resubmit a completed image request |
| Shared scene updates | Named input revisions, explicit take bindings, impact preview and selected-output application | Dependencies are recorded input assets, not inferred semantic relationships; affected downstream work waits for a selected completed upstream output |
| Branch from a video moment | Save a real decoded frame and its timestamp, parent video and source hash; configure a fresh H3 first-frame take | Frame extraction is local; further video generation occurs only after explicit submission and is not continuation-guaranteed |
| Favorites and selection | Stored take favorite and project/shot selection | Reopening uses persisted records |
| Transparent jobs | Internal state plus real Router status, queue position and execution IDs | No invented percentage; COMPLETED plus an error is failure |
| Durable media | Managed local media plus content hashes | Provider URLs are not the sole asset store |
| Download | Media endpoint supports an attachment response | Delivered bytes can be checked against stored SHA-256 |
| Production package | Manifest and media ZIP; relationship validation; fresh import IDs | Imported execution history is archived and does not dispatch again |
| Imported examples | Explicit `imported` provenance | The earlier ComfyUI workflows are references, not Router-executable graphs |
| Experimental/unavailable features | Registry status and this matrix | Catalog/schema access does not claim live success |
| Model/route transparency | [Per-model audit](../shared/model-audit.ts) and [license/route evidence](model-route-audit.md) | Requested provider is not proof of actual serving provider; no implemented route is certified as all-stage open-weight execution |
