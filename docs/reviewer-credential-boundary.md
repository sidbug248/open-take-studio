# Reviewer credential boundary

Reviewer workspaces have separate SQLite repositories and managed media directories. A reviewer cookie is a random opaque token whose hash is stored in the private vault. The cookie lasts seven days. There is no reviewer account recovery: export work before abandoning the browser session.

Connected Comfy keys are encrypted with AES-256-GCM under the deployment's 32-byte `OTS_CREDENTIAL_ENCRYPTION_KEY`. Session ID, opaque credential scope and expiry are authenticated encryption data. Keys expire after twelve hours. Disconnect and expiry erase the encrypted value and abort credential leases; the original key's HMAC fingerprint remains so an accepted execution cannot accidentally be polled or replayed under another workspace key. Reconnecting the same key preserves request IDs and idempotency. A different key requires a new reviewer workspace. No reviewer key is written to project records, media, browser storage, production packages or logs.

Connection verification makes a read-only authenticated Router catalogue request. It optionally reads the documented Cloud billing balance; lack of Cloud billing permission does not invalidate a Router key. An accepted key does not prove credits, model availability or successful generation. Invalid credentials, denied Router permission and an observed insufficient balance are distinct outcomes. No inference is submitted to verify a connection.

SDK 0.5.0 exposes Router credentials through module-global `comfy.config`, without a per-call key option. Each Router operation therefore runs in a disposable JavaScript worker with one explicit credential and an empty inherited environment. The HTTP process never switches global SDK credentials. At most four Router operations run concurrently, with a bounded queue. Native workflows use the SDK's explicit per-instance `Comfy({apiKey})`; their operation limit is four globally, with four separate optional progress streams. Native node discovery and temporary uploaded-media caches are scoped to the credential identity. Media processing and export workers receive allowlisted environment variables only.

An internal `job_credentials` table binds each admitted job to an opaque credential scope. It is excluded from portable production packages. Missing, expired or disconnected credentials suspend work before increasing admission attempts. Reconnection resumes the existing request; ambiguous native submissions still require their existing Cloud execution ID. Archived imported jobs never run.

The owner backup service creates a consistent snapshot of the owner's SQLite database, its referenced media and prepared presentation files. It does not recursively copy reviewer databases or the credential vault. Reviewer storage and the encrypted vault currently persist on the mounted disk; automatic off-host reviewer backups are not configured. Project export remains available without a connected key.

Verified interfaces: installed `@comfyorg/sdk` 0.5.0 `sdk/models.d.ts`, `sdk/modelRequests.d.ts`, `sdk/credentials.js`, and `sdk/client.d.ts`; [Router quickstart](https://docs.comfy.org/development/comfy-router/quickstart); [Cloud API schema](https://raw.githubusercontent.com/Comfy-Org/docs/main/openapi-cloud.yaml). Automated tests use mocked provider responses; a separate read-only check with the existing unfunded key verified the `insufficient_credits` connection state without generating media.
