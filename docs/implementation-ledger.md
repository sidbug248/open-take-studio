## Working application and continuity

React and a server-side Node layer provide the project library, media stage, contextual creation form, take ribbon, favorites, source library, shots, history, comparison, recipes and downloads. Charcoal/iris styling and real project media carry the interface. Canonical image, video, audio, text, vector, mesh, scene and playable types drive the catalogue filters; text transcription has a readable document path rather than a 3D fallback.

Projects, assets, takes, jobs, shots, branches, settings snapshots and recipes persist in SQLite with application-owned media. Editing a later stage reuses unchanged source assets. Recorded changes describe the submitted prompt, supported settings, input references, source and parent; they do not promise deterministic pixels or permanent identity. Images compare directly. Video comparisons start together and stop at the shortest clip, without time stretching, with take-A audio.

Named scene inputs and explicit story-fact dependencies produce impact plans before application. Scene operations use immutable revisions, project-scoped serialization, durable operation receipts and atomic local-page commits. Replaying an intent returns its recorded outcome; a changed body cannot silently reuse that identity. This structured workflow does not claim a general freeform node canvas.

Shot batches freeze exact per-shot request bodies and identities in browser storage before admission, accept up to six shots and reuse completed selected takes by default. Accepted jobs persist server-side. The current browser check reused the two Mara shots with zero new jobs and reopened both saved outcomes after reload. Camera presets append editable language and are explicitly labelled prompt-guided; they do not enforce a model camera path.
